# V0.2 Agent Runtime — 多轮会话 + LangGraph Checkpoint + LangSmith 可观测性

## 1. 概述

- **目标**：在 V0.1 基础对话上增加多轮会话持久化、LangGraph Checkpoint 状态管理和 LangSmith 可观测性
- **背景**：V0.1 实现了一次性对话，但没有会话记忆和调试能力。V0.2 引入 PostgreSQL 持久化存储、LangGraph 的 checkpoint 机制和 LangSmith 链路追踪
- **状态**：✅ 已完成

### 2.3 关键数据结构

**LangGraph State**：
```python
# ai_service/graph/state.py
class State(TypedDict):
    messages: list          # 对话消息列表
    conversation_id: str    # 会话 ID
    active_agent: str       # 活跃 Agent 名称
    iteration_count: int    # 当前迭代次数
    current_tool: str       # 当前工具名
    tool_input: dict        # 工具输入参数
    tool_result: str        # 工具执行结果（JSON）
    tool_steps: list        # 工具步骤记录（含耗时、状态）
    last_tool_name: str     # 上次工具名（去重检查）
    last_tool_query: str    # 上次查询（去重检查）
    consecutive_search_count: int  # 连续搜索次数
    reasoning_steps: list   # 推理步骤日志
    last_guard_reason: dict # 最后策略拦截原因
    route: str              # 路由决策：agent/tool/chart_planner/answer
    chart_specs: list       # 图表规格列表
    generation: str         # 最终生成文本
```

**ReAct 提示词**（`ai_service/graph/nodes.py:30-55`）：

### 2.4 关键代码路径

**ReAct 循环流程**（`ai_service/graph/nodes.py:140-341`）：

1. `agent_node` 构建 ReAct 系统提示词 + 工具列表 + Observation（上次工具结果）
2. 调用 LLM（JSON Mode, `response_format: {"type": "json_object"}`）
3. 解析 LLM 返回 JSON：
   - `{"action": "tool", "tool": "search", "query": "..."}` → 路由到 `tool_node`
   - `{"actions": [{...}, {...}]}` → 并行工具执行
   - `{"action": "final_answer"}` → 路由到 `chart_planner_node` → `answer_node`
4. `tool_node` 执行工具 → 结果注入 State → 循环回 `agent_node`
5. 策略护栏：
   - **最大迭代**：`MAX_ITERATIONS`（默认 5），超限强制 `final_answer`
   - **连续搜索去重**：`MAX_CONSECUTIVE_SEARCH_CALLS`（默认 2），超限强制结束
   - **重复调用拦截**：相同工具+相同查询 → 拦截
   - **首次强制搜索**：第一轮 LLM 输出 `final_answer` → 自动注入搜索

## 7. 风险与注意事项

- **JSON Mode 依赖**：agent_node 强制使用 `response_format: {"type": "json_object"}`，部分模型不支持或支持不稳定
- **State 膨胀**：多轮对话中 messages 数组持续增长，需要控制 token 预算
- **LangSmith 成本**：启用后每个 LLM 调用都会上报，大量使用会增加 LangSmith 费用
- **并行工具执行边界**：`asyncio.gather` 并行执行，但结果合并是同步的，需注意超时设置

# V1.3 Workflow Engine — Human-in-the-loop

> **注意**：本文档基于路线图推演，实际实现可能不同。

## 1. 概述

- **目标**：实现人机协作节点：人工审批、人工确认和等待输入，使 Workflow 能在关键决策点暂停等待人工介入
- **背景**：V1.2 实现了完整的流程控制。V1.3 使 Workflow 从全自动执行升级为可人机协作，适用于需要人工判断的审批、验证和输入场景
- **状态**：📋 规划中

### 2.2 核心组件

| 组件 | 职责 |
|------|------|
| `ApprovalNode` | 暂停 Workflow 等待审批（通过/驳回） |
| `ConfirmNode` | 暂停等待用户确认（确认/取消） |
| `InputNode` | 暂停等待用户输入（文本/文件上传） |
| `TaskQueue` | 待处理的人工任务队列 |
| `NotificationService` | 通知服务（SSE/WebSocket/Email） |
| `TimeoutManager` | 任务超时和自动升级处理 |

### 2.3 关键数据结构

```python
@dataclass
class HumanTask:
    """人工任务"""
    task_id: str
    workflow_run_id: str
    node_id: str
    type: str              # approval | confirm | input
    title: str             # 任务标题
    description: str       # 任务描述
    context: dict          # 上下文数据（供界面展示）
    status: str            # pending | approved | rejected | timeout
    assigned_to: str | None  # 指定审批人
    created_at: float
    timeout_at: float | None
    completed_at: float | None
    result: dict | None    # 用户响应

@dataclass
class ApprovalNode(WorkflowNode):
    """审批节点"""
    type: str = "approval"
    title: str
    description: str
    options: list[str]     # ["approve", "reject"]
    require_comment: bool = False
    timeout_minutes: int = 60
    escalate_on_timeout: str | None = None  # 超时升级策略

@dataclass
class InputNode(WorkflowNode):
    """输入节点"""
    type: str = "input"
    prompt: str                         # 输入提示
    input_type: str = "text"            # text | file | select
    validation: dict | None = None      # 输入验证规则
    timeout_minutes: int = 30
```

### 2.4 Workflow 暂停与恢复

```python
class HumanInLoopManager:
    async def pause_for_human(
        self, node: HumanTask, context: dict
    ) -> HumanTaskResult:
        # 1. 创建 HumanTask，存入 TaskQueue
        task = HumanTask(...)
        await self.task_queue.enqueue(task)

        # 2. 持久化 Workflow 状态（Checkpoint）
        await self.checkpoint_manager.save(workflow_run_id, state)

        # 3. 发送通知
        await self.notification_service.notify(task)

        # 4. 阻塞等待用户响应（或超时）
        try:
            result = await asyncio.wait_for(
                self._wait_for_response(task.task_id),
                timeout=task.timeout_minutes * 60,
            )
        except asyncio.TimeoutError:
            result = self._handle_timeout(task)

        # 5. 恢复 Workflow 执行
        return result

    async def _wait_for_response(self, task_id: str) -> HumanTaskResult:
        """监听用户响应（通过 WebSocket 或轮询）"""
        while True:
            task = await self.task_queue.get(task_id)
            if task.status != "pending":
                return HumanTaskResult(
                    task_id=task_id,
                    status=task.status,
                    response=task.result,
                )
            await asyncio.sleep(1)
```

## 3. Phase 拆分

| Phase | 名称 | 目标 | 关键交付物 | 预估工作量 |
|-------|------|------|-----------|-----------|
| Phase 1 | HumanTask Model + Queue | 任务模型+队列 | HumanTask、TaskQueue（PostgreSQL） | 2-3d |
| Phase 2 | Approval Node | 审批节点 | ApprovalNode、前端审批界面 | 3-4d |
| Phase 3 | Confirm + Input Node | 确认+输入节点 | ConfirmNode、InputNode、输入验证 | 2-3d |
| Phase 4 | Notification Service | 通知推送 | SSE/WebSocket 推送、Email 通知 | 2-3d |
| Phase 5 | Timeout + Escalation | 超时+升级 | TimeoutManager、升级策略 | 2-3d |
| Phase 6 | Workflow 暂停/恢复 | 状态持久化+恢复 | Checkpoint 集成、断点恢复 | 2-3d |

## 6. 验收标准

- [ ] AC1: Workflow 到达审批节点时暂停并在前端显示审批任务
- [ ] AC2: 审批通过后 Workflow 继续执行下游节点
- [ ] AC3: 审批驳回后 Workflow 进入指定的失败/回退路径
- [ ] AC4: 输入节点等待用户提交文本后继续执行
- [ ] AC5: 任务超时后按策略自动处理（默认驳回/自动通过/升级）
- [ ] AC6: 关闭浏览器后重新打开能看到待处理任务

## 7. 风险与注意事项

- **超时策略**：审批超时自动拒绝可能丢失紧急审批，需灵活配置
- **通知可靠性**：SSE 断连后用户可能错过审批，需要任务队列兜底
- **并发审批**：同一 Workflow 的多个审批节点需串行处理（保持业务顺序）

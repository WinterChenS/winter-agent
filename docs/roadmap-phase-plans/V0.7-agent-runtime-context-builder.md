# V0.7 Agent Runtime — Context Builder

> **注意**：本文档基于路线图推演，实际实现可能不同。

## 1. 概述

- **目标**：实现会话、文件、Memory、Knowledge 上下文的自动构建和注入，为 Agent 提供完整的运行上下文
- **背景**：V0.6 的工具系统已成熟，但 Agent 每次对话都从零开始。V0.7 引入 Context Builder，自动收集和组装运行时上下文
- **状态**：📋 规划中

### 2.2 核心组件

| 组件 | 职责 |
|------|------|
| `SessionContextProvider` | 当前会话历史、对话摘要、活跃 Agent 信息 |
| `FileContextProvider` | 用户上传文件的内容提取和引用 |
| `MemoryContextProvider` | 长期记忆：用户偏好、历史决策、关键事实 |
| `KnowledgeContextProvider` | 知识库检索：向量搜索 + 全文搜索匹配 |
| `ContextAssembler` | 上下文融合：优先级排序、去重、token 预算控制 |
| `ContextInjector` | 将组装好的上下文注入 system prompt |

### 2.3 上下文优先级策略

```
优先级: Session > Files > Memory > Knowledge

Session Context (高优先级)
  ├── 最近 N 轮对话（默认 10 轮）
  ├── 对话摘要（超出窗口时自动生成）
  └── 活跃 Agent 的能力信息

File Context (中高优先级)
  ├── 当前上传文件的内容片段
  ├── 文件类型元数据（PDF/Word/Excel/PPT/Markdown）
  └── 文件引用路径

Memory Context (中优先级)
  ├── 用户偏好设置
  ├── 历史关键决策记录
  └── 事实性知识片段

Knowledge Context (低优先级)
  ├── 相关文档片段（RAG 检索）
  ├── 代码库上下文
  └── 企业知识库匹配
```

### 2.4 Token 预算管理

```python
class TokenBudget:
    """管理系统提示词的 token 分配"""

    def __init__(self, total_budget: int = 8000):
        self.total = total_budget
        self.allocations = {
            "system_base": 500,      # 基础系统提示
            "session": 2000,         # 会话上下文
            "files": 1500,           # 文件上下文
            "memory": 1000,          # 记忆上下文
            "knowledge": 1500,       # 知识上下文
            "tools": 500,            # 工具定义
            "reserved": 1000,        # 响应预留
        }

    def allocate(self, provider: str, tokens: int) -> int:
        """为上下文提供者分配 token，返回实际分配数"""
        budget = self.allocations.get(provider, 0)
        return min(tokens, budget)
```

## 3. Phase 拆分

| Phase | 名称 | 目标 | 关键交付物 | 预估工作量 |
|-------|------|------|-----------|-----------|
| Phase 1 | Session Context | 会话历史和摘要 | SessionContextProvider、摘要生成器 | 2-3d |
| Phase 2 | File Context | 文件上传与内容提取 | FileContextProvider、文件解析器 | 3-4d |
| Phase 3 | Memory Context | 长期记忆存储检索 | MemoryContextProvider、记忆向量化 | 3-4d |
| Phase 4 | Knowledge Context | 知识库 RAG 检索 | KnowledgeContextProvider、向量搜索 | 3-4d |
| Phase 5 | Context Assembler | Token 预算+优先级合并 | ContextAssembler、TokenBudget | 2-3d |
| Phase 6 | Context Injector | 系统提示注入 | ContextInjector、模板渲染 | 1-2d |

## 4. 接口设计

### 内部接口

```python
class ContextProvider(ABC):
    """上下文提供者抽象"""

    @abstractmethod
    async def gather(self, request: ContextRequest) -> ContextFragment:
        """收集上下文片段"""

@dataclass
class ContextRequest:
    session_id: str
    user_query: str
    agent_id: str | None
    max_tokens: int

@dataclass
class ContextFragment:
    provider: str          # session/files/memory/knowledge
    content: str           # 上下文文本
    tokens: int            # token 计数
    priority: int          # 优先级（越小越高）
    metadata: dict         # 来源元数据
```

## 6. 验收标准

- [ ] AC1: 当前会话历史自动注入 Agent 上下文（最近 10 轮）
- [ ] AC2: 用户上传文件后内容片段出现在 Agent 上下文中
- [ ] AC3: 超出上下文窗口时自动生成对话摘要替代完整历史
- [ ] AC4: 四个上下文提供者按优先级合并，不重复
- [ ] AC5: Token 预算控制：总上下文不超过模型限制

## 7. 风险与注意事项

- **Token 计算精度**：不同模型的 tokenizer 不同，tiktoken 估算可能不精确
- **上下文窗口膨胀**：多提供者同时激活时可能超出预算，需要截断策略
- **Memory 冷启动**：新用户无历史记忆，需要合理的默认值
- **与 Knowledge Engine 重叠**：V0.7 的 Knowledge Context 是轻量版，V1.6+ 的 Knowledge Engine 会提供完整 RAG 能力

# V1.0 Agent Runtime — Runtime SDK

> **注意**：本文档基于路线图推演，实际实现可能不同。

## 1. 概述

- **目标**：提供统一的 Agent Runtime SDK，使所有 Agent 共用标准化的运行时 API。这是 Agent Runtime 阶段的最终里程碑
- **背景**：V0.9 实现了运行时的稳定性保障。V1.0 将这些能力封装为 SDK，提供简洁、一致的 API 供内部 Agent 和外部集成使用
- **状态**：📋 规划中

### 2.2 核心组件

| 组件 | 职责 |
|------|------|
| `AgentRuntime` | SDK 入口，提供 Agent 创建、运行、流式输出、取消等核心 API |
| `AgentConfig` | Agent 配置：模型、工具、提示词、策略、上下文提供者 |
| `RunResult` | 统一运行结果：输出、工具调用、图表、token 用量、事件 |
| `AgentContext` | 运行时上下文：会话、文件、记忆、知识（来自 V0.7） |
| `ToolProvider` | 工具提供者接口：注册、发现、Schema |
| `EventStream` | 事件流接口：订阅、过滤、转换 |

### 2.3 Python SDK API

```python
from winter_agent import AgentRuntime, AgentConfig, ToolProvider

# 1. 创建 Runtime
runtime = AgentRuntime(
    base_url="http://localhost:8000",
    api_key="your-api-key",
)

# 2. 配置 Agent
agent = AgentConfig(
    name="data-analyst",
    model="gpt-4",
    system_prompt="You are a data analyst...",
    tools=["search", "browser", "sandbox"],
    context_providers=["session", "memory"],
    strategy="sequential",
)

# 3. 运行（非流式）
result: RunResult = await runtime.run(agent, "分析 Q2 销售数据")
print(result.output)         # 最终输出文本
print(result.token_usage)    # Token 统计

# 4. 流式运行
async for event in runtime.stream(agent, "生成销售图表"):
    match event.type:
        case "token":
            print(event.delta, end="", flush=True)
        case "tool.invoke":
            print(f"\n🔧 Calling {event.tool_name}...")
        case "chart":
            print(f"\n📊 Chart: {event.chart_spec.title}")

# 5. 取消运行
await runtime.cancel(run_id)

# 6. 自定义工具
class MyTool(ToolProvider):
    name = "my_tool"
    description = "Custom tool"
    parameters = {"type": "object", "properties": {...}}

    async def execute(self, input: dict) -> dict:
        return {"result": "done"}

runtime.register_tool(MyTool())
```

### 2.4 REST API（统一网关）

```
POST   /v1/agents                    # 创建 Agent 定义
GET    /v1/agents                    # 列出 Agent
GET    /v1/agents/{id}              # 获取 Agent 详情
PUT    /v1/agents/{id}              # 更新 Agent
DELETE /v1/agents/{id}              # 删除 Agent

POST   /v1/runs                     # 创建 Run（非流式）
GET    /v1/runs/{id}               # 获取 Run 状态
GET    /v1/runs/{id}/stream        # SSE 流式 Run
POST   /v1/runs/{id}/cancel        # 取消 Run
GET    /v1/runs/{id}/events        # 获取 Run 事件

POST   /v1/tools                    # 注册工具
GET    /v1/tools                    # 列出工具

GET    /v1/context/{session_id}     # 获取会话上下文
```

## 4. 接口设计

### Python SDK 核心类型

```python
@dataclass
class AgentConfig:
    name: str
    model: str
    system_prompt: str
    tools: list[str]
    context_providers: list[str]         # session/files/memory/knowledge
    strategy: str = "sequential"         # sequential/parallel/supervisor
    temperature: float = 0.7
    max_iterations: int = 5
    timeout_ms: int = 120000

@dataclass
class RunResult:
    run_id: str
    status: str                          # completed/error/cancelled
    output: str
    tool_calls: list[ToolCallResult]
    chart_specs: list[ChartSpec]
    token_usage: TokenUsage
    elapsed_ms: int
    events: list[RuntimeEvent]

@dataclass
class TokenUsage:
    prompt_tokens: int
    completion_tokens: int
    total_tokens: int
    cost_usd: float                      # 费用估算
```

- [ ] AC7: SDK 文档完整覆盖所有公开 API

## 7. 风险与注意事项

- **API 稳定性**：V1.0 的 API 语义需要仔细设计，因为后续版本将在此基础上构建
- **SDK 多语言维护成本**：Python/Java/TypeScript 三个 SDK 需保持功能一致性
- **REST vs SDK**：REST API 的延迟高于直接 SDK 调用，需要明确各自适用场景
- **版本兼容**：V1.0 的 API 需支持向后兼容，后续版本新增字段使用 optional

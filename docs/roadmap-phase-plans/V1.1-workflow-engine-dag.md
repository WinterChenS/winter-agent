# V1.1 Workflow Engine — DAG Workflow Engine

> **注意**：本文档基于路线图推演，实际实现可能不同。

## 1. 概述

- **目标**：实现 DAG（有向无环图）Workflow Engine，支持节点+边的声明式工作流定义、DAG 验证和拓扑排序执行
- **背景**：V1.0 的 Runtime SDK 提供了统一 Agent 执行 API。V1.1 在此基础上构建 DAG 编排引擎，使多个 Agent/工具调用可以组织为有依赖关系的工作流
- **状态**：📋 规划中

## 2. 技术方案

### 2.1 架构概览

```

│  │ DAG Parser   │───▶│ DAG Validator│───▶│Topological    │    │
│  │ (节点+边解析) │    │ (环检测)      │    │Sorter        │    │

```

### 2.2 核心组件

| 组件 | 职责 |
|------|------|
| `WorkflowDefinition` | 声明式工作流定义（节点列表 + 边列表） |
| `DAGParser` | 解析 YAML/JSON 工作流定义 |
| `DAGValidator` | DAG 环检测（DFS/Kahn 算法） |
| `TopologicalSorter` | 拓扑排序，生成执行层级 |
| `DAGExecutor` | 按拓扑顺序执行节点，同层并行 |
| `NodeExecutor` | 单节点执行器（Agent 调用/工具调用/子流程） |

### 2.3 关键数据结构

```python
@dataclass
class WorkflowDefinition:
    """声明式工作流定义"""
    name: str
    version: str
    nodes: list[WorkflowNode]
    edges: list[WorkflowEdge]
    defaults: WorkflowDefaults  # 默认超时、重试等

@dataclass
class WorkflowNode:
    id: str                      # 节点唯一 ID
    type: str                    # agent | tool | subworkflow | script
    config: dict                 # 节点配置（Agent 名/工具名/参数）
    inputs: dict | None          # 输入映射（from upstream）

@dataclass
class WorkflowEdge:
    from_node: str               # 上游节点 ID
    to_node: str                 # 下游节点 ID
    condition: str | None        # 条件表达式（可选）
    data_mapping: dict | None    # 数据映射（output.field → input.field）

@dataclass
class ExecutionLevel:
    """拓扑排序后的执行层级"""
    level: int                   # 层级编号（0-based）
    nodes: list[str]             # 该层级可并行的节点 ID 列表
```

### 2.4 DAG 验证算法

```python
class DAGValidator:
    def validate(self, workflow: WorkflowDefinition) -> ValidationResult:
        # 1. 节点 ID 唯一性检查
        # 2. 边引用有效性（from/to 节点存在）
        # 3. 环检测（DFS 三色标记法）
        # 4. 连通性检查（可选：孤立节点警告）
        return ValidationResult(valid=True, warnings=[])

    def _detect_cycle(self, nodes, edges) -> list[str] | None:
        """DFS 三色标记环检测，返回环路径或 None"""
        WHITE, GRAY, BLACK = 0, 1, 2
        color = {n.id: WHITE for n in nodes}
        parent = {}
        for node in nodes:
            if color[node.id] == WHITE:
                cycle = self._dfs(node.id, edges, color, parent)
                if cycle:
                    return cycle
        return None
```

### 2.5 执行模型

```python
class DAGExecutor:
    async def execute(self, workflow: WorkflowDefinition) -> WorkflowResult:
        # 1. 拓扑排序 → 生成执行层级
        levels = self._topological_sort(workflow)

        # 2. 逐层执行
        results: dict[str, NodeResult] = {}
        for level in levels:
            # 同层节点并行执行
            tasks = [
                self._execute_node(node_id, workflow, results)
                for node_id in level.nodes
            ]
            level_results = await asyncio.gather(*tasks)
            for node_id, result in zip(level.nodes, level_results):
                results[node_id] = result

        return WorkflowResult(status="completed", node_results=results)
```

## 3. Phase 拆分

| Phase | 名称 | 目标 | 关键交付物 | 预估工作量 |
|-------|------|------|-----------|-----------|
| Phase 1 | Workflow Definition Model | 定义工作流声明模型 | WorkflowDefinition/Node/Edge 数据类 | 2-3d |
| Phase 2 | DAG Parser + Validator | YAML/JSON 解析 + 环检测 | DAGParser、DAGValidator | 2-3d |
| Phase 3 | Topological Sorter | 拓扑排序 + 执行层级生成 | TopologicalSorter、层级并行检测 | 2-3d |
| Phase 4 | DAG Executor | 逐层并行执行引擎 | DAGExecutor、NodeExecutor | 3-4d |
| Phase 5 | Result Passing | 上下游数据传递 | data_mapping 引擎、表达式求值 | 2-3d |
| Phase 6 | SDK 集成 | 集成到 V1.0 Runtime SDK | WorkflowRuntime API | 2-3d |

## 6. 验收标准

- [ ] AC1: YAML/JSON 工作流定义可解析并验证
- [ ] AC2: 含环的 DAG 被正确检测并拒绝
- [ ] AC3: 简单线性工作流（A→B→C）按顺序执行
- [ ] AC4: 分支工作流（A→B, A→C）中 B 和 C 并行执行
- [ ] AC5: 上游节点输出正确传递给下游节点输入
- [ ] AC6: SDK 提供 `runtime.run_workflow()` API

## 7. 风险与注意事项

- **DAG 复杂度**：大型 DAG（100+ 节点）的验证和执行性能需要基准测试
- **循环依赖**：DAG 不应有环，但用户可能错误定义；验证器必须可靠
- **执行隔离**：同层节点并行执行时的资源竞争和错误隔离

# V1.5 Workflow Engine — Workflow Designer

> **注意**：本文档基于路线图推演，实际实现可能不同。

## 1. 概述

- **目标**：实现可视化拖拽 Workflow 设计器，让用户通过图形界面创建、编辑和管理 DAG 工作流
- **背景**：V1.4 完成了 Workflow Engine 的全部后端能力。V1.5 提供前端可视化工具，降低 Workflow 创建门槛，面向非技术用户
- **状态**：📋 规划中

### 2.2 核心组件

|------|------|
| `WorkflowCanvas` | 主画布：拖拽、连线、缩放、平移 |

```typescript
// 画布节点（ReactFlow Node）
interface DesignerNode {
  id: string;
  type: string;          // agent | tool | condition | loop | approval | subworkflow
  position: { x: number; y: number };
  data: {
    label: string;
    config: WorkflowNodeConfig;
    status?: 'valid' | 'warning' | 'error';
  };
}

// 画布边（ReactFlow Edge）
interface DesignerEdge {
  id: string;
  source: string;
  target: string;
  sourceHandle?: string;  // 条件分支出口
  data?: {
    condition?: string;
    label?: string;
  };
}

// 画布状态
interface CanvasState {
  nodes: DesignerNode[];
  edges: DesignerEdge[];
  selectedNodeId: string | null;
  isValid: boolean;
  errors: ValidationError[];
}
```

### 2.6 序列化与反序列化

```typescript
class WorkflowSerializer {
  // 画布 → WorkflowDefinition
  serialize(canvas: CanvasState): WorkflowDefinition {
    return {
      name: canvas.name,
      version: canvas.version,
      nodes: canvas.nodes.map(n => ({
        id: n.id,
        type: n.type,
        config: n.data.config,
        position: { x: n.position.x, y: n.position.y },  // 保留布局
      })),
      edges: canvas.edges.map(e => ({
        from_node: e.source,
        to_node: e.target,
        condition: e.data?.condition,
      })),
    };
  }

  // WorkflowDefinition → 画布（加载已有 Workflow）
  deserialize(definition: WorkflowDefinition): CanvasState {
    return {
      nodes: definition.nodes.map((n, i) => ({
        id: n.id,
        type: n.type,
        position: n.position || autoLayout(definition, i),
        data: {
          label: n.id,
          config: n.config,
        },
      })),
      edges: definition.edges.map(e => ({
        id: `${e.from_node}-${e.to_node}`,
        source: e.from_node,
        target: e.to_node,
        data: { condition: e.condition },
      })),
    };
  }
}
```

### 2.7 实时验证

```typescript
class DAGValidator {
  validate(canvas: CanvasState): ValidationResult {
    const errors: ValidationError[] = [];

    // 1. 孤立的 Agent/Tool 节点（没有边）
    const connected = new Set(canvas.edges.flatMap(e => [e.source, e.target]));
    canvas.nodes
      .filter(n => n.type !== 'start' && !connected.has(n.id))
      .forEach(n => errors.push({ nodeId: n.id, message: '未连接的节点' }));

    // 2. 环检测（DFS）
    const cycle = this.detectCycle(canvas.nodes, canvas.edges);
    if (cycle) errors.push({ message: `检测到环: ${cycle.join(' → ')}` });

    // 3. 必填配置检查
    canvas.nodes.forEach(n => {
      const schema = NODE_TYPES[n.type]?.configSchema;
      if (schema) this.validateConfig(n.id, n.data.config, schema, errors);
    });

    return { valid: errors.length === 0, errors };
  }
}
```

## 3. Phase 拆分

| Phase | 名称 | 目标 | 关键交付物 | 预估工作量 |
|-------|------|------|-----------|-----------|
| Phase 1 | Canvas Core | 画布框架+拖拽+连线 | ReactFlow 集成、CanvasState、Zustand store | 3-4d |
| Phase 2 | Node Registry | 节点类型定义+注册 | NODE_TYPES、configSchema、NodePanel | 2-3d |
| Phase 3 | Property Panel | 节点配置编辑 | PropertyPanel、动态表单、验证 | 3-4d |
| Phase 4 | Serialization | 画布↔定义转换 | WorkflowSerializer、YAML 导入/导出 | 2-3d |
| Phase 5 | DAG Validation | 实时前端验证 | DAGValidator、环检测、错误提示 | 2-3d |
| Phase 6 | Run & Test | 设计器中测试执行 | 一键运行、执行进度、结果预览 | 3-4d |
| Phase 7 | Auto Layout | 自动布局+美化 | dagre/elkjs 集成、手动调整 | 2-3d |

## 6. 验收标准

- [ ] AC1: 拖拽节点到画布并连线创建 DAG Workflow
- [ ] AC2: 节点属性面板正确反映节点类型特有配置
- [ ] AC3: 实时 DAG 验证：环检测显示错误，无环显示"验证通过"
- [ ] AC4: 保存 Workflow → 加载后画布状态完整恢复
- [ ] AC5: 导出 YAML/JSON 后在其他环境可导入执行
- [ ] AC6: 从设计器一键运行 Workflow 并查看执行进度

## 7. 风险与注意事项

- **画布性能**：100+ 节点时 ReactFlow 渲染和布局性能需要基准测试
- **自动布局质量**：dagre 默认布局可能不符合直觉，需允许手动调整
- **版本兼容**：Designer 版本与 Workflow Engine API 版本需保持一致
- **节点类型扩展**：后续 Skill Engine 阶段可能新增节点类型，NODE_TYPES 需支持插件化注册

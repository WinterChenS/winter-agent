# V0.8 Agent Runtime — Event Bus

> **注意**：本文档基于路线图推演，实际实现可能不同。

## 1. 概述

- **目标**：建立 Tool、LLM、Workflow 全事件流系统，实现事件驱动的 Agent 运行时架构
- **背景**：V0.7 的 Context Builder 为 Agent 提供了静态上下文。V0.8 引入 Event Bus 使运行时组件之间可以松耦合地通信，支持事件驱动的响应和可观测性
- **状态**：📋 规划中

### 2.2 核心组件

| 组件 | 职责 |
|------|------|
| `EventBus` | 核心发布/订阅总线，支持 topic 过滤和通配符 |
| `EventPublisher` | 事件发布接口，注入到各 Node |
| `EventSubscriber` | 事件订阅接口，注册消费者回调 |
| `EventSchema` | 标准化事件格式（type, timestamp, source, payload） |
| `EventRouter` | 基于 topic 的事件路由（支持 wildcard） |
| `EventStore` | 可选的事件持久化（用于审计和回放） |

### 2.3 事件格式

```python
@dataclass
class RuntimeEvent:
    """标准化运行时事件"""
    event_id: str              # UUID
    event_type: str            # llm.request / tool.invoke / ...
    timestamp: float           # Unix timestamp ms
    source: str                # 事件源组件名
    trace_id: str              # 分布式追踪 ID
    span_id: str               # Span ID
    payload: dict              # 事件负载
    metadata: dict             # 扩展元数据

    def to_sse(self) -> str:
        return f"data: {json.dumps(self.to_dict())}\n\n"
```

### 2.4 事件类型定义

```python
class EventTypes:
    # LLM Events
```

## 3. Phase 拆分

| Phase | 名称 | 目标 | 关键交付物 | 预估工作量 |
|-------|------|------|-----------|-----------|
| Phase 1 | EventBus Core | 发布/订阅基础架构 | EventBus、EventPublisher/Subscriber | 2-3d |
| Phase 2 | LLM Events | LLM 调用事件化 | llm.request/response/token 事件注入 | 2-3d |
| Phase 3 | Tool Events | 工具调用事件化 | tool.invoke/result/error 事件注入 | 1-2d |
| Phase 4 | Graph Events | LangGraph 节点事件化 | graph.enter/exit/error 事件 | 2-3d |
| Phase 5 | SSE 集成 | 事件→前端 SSE 推送 | Event→SSE 适配器 | 1-2d |
| Phase 6 | 持久化 + 回放 | 事件存储和回放 | EventStore、查询 API | 2-3d |

## 4. 接口设计

```python
# EventBus 核心 API
class EventBus:
    async def publish(self, event: RuntimeEvent) -> None: ...
    async def subscribe(
        self, topic: str, handler: Callable, filter: dict | None = None
    ) -> Subscription: ...
    async def unsubscribe(self, subscription_id: str) -> None: ...

# 消费者注册
bus.subscribe("tool.*", metrics_collector.on_tool_event)
bus.subscribe("llm.*", audit_logger.on_llm_event)
bus.subscribe("*.error", alert_manager.on_error_event)
```

## 5. 依赖关系

- **前置版本**：V0.7（Context Builder）
- **依赖模块**：所有 Node 需要集成 EventPublisher
- **外部依赖**：可选 Redis/RabbitMQ（分布式事件总线）

## 6. 验收标准

- [ ] AC1: 每次 LLM 调用自动发出 llm.request + llm.response 事件
- [ ] AC2: 工具调用全生命周期事件（invoke→progress→result/error）完整
- [ ] AC3: 事件可通过 SSE 实时推送到前端
- [ ] AC4: 事件持久化后支持按 trace_id 查询完整链路
- [ ] AC5: 事件订阅支持 wildcard topic 匹配（如 `tool.*`）

## 7. 风险与注意事项

- **性能影响**：同步事件发布可能阻塞主流程，需要异步发布
- **事件风暴**：大量 token 事件可能 flooding，需要采样或批量发送
- **技术选型**：in-process pub/sub（简单但无持久化）vs 外部 MQ（复杂但可靠）需权衡
- **与 OpenTelemetry 重叠**：V4.0 的可观测性方案可能与 Event Bus 重叠，需要提前规划边界

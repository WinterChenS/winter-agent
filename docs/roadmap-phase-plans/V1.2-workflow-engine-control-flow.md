# V1.2 Workflow Engine — 条件、循环、并行、子流程、动态节点

> **注意**：本文档基于路线图推演，实际实现可能不同。

## 1. 概述

- **目标**：在 V1.1 DAG 引擎基础上增加流程控制能力：条件分支、循环、并行扇出、子流程嵌套和动态节点
- **背景**：V1.1 实现了基础的线性 DAG 执行。V1.2 使 Workflow 支持编程语言级别的控制流，实现真正的复杂任务编排
- **状态**：📋 规划中

### 2.2 控制流节点类型

| 节点类型 | 描述 | 配置参数 |
|---------|------|---------|
| `condition` | 条件分支 | `expression`: 条件表达式（Jinja2/JSONPath） |
| `loop` | 循环遍历 | `iterator`: 迭代数据源, `max_iterations`: 最大迭代 |
| `parallel` | 并行扇出 | `fan_out`: 扇出表达式，`max_concurrency`: 最大并发 |
| `subworkflow` | 子流程 | `workflow_ref`: 引用的子 Workflow ID |
| `dynamic` | 动态节点 | `resolver`: LLM prompt 或 template |

### 2.3 关键数据结构

```python
@dataclass
class ConditionNode(WorkflowNode):
    """条件分支节点"""
    type: str = "condition"
    branches: list[ConditionBranch]  # 分支列表

@dataclass
class ConditionBranch:
    expression: str                 # Jinja2 条件表达式
    target_node: str                # 条件满足时的目标节点
    description: str                # 分支描述

@dataclass
class LoopNode(WorkflowNode):
    """循环节点"""
    type: str = "loop"
    iterator: str                   # 迭代数据源表达式
    body: WorkflowDefinition        # 循环体（子 DAG）
    max_iterations: int = 100       # 安全上限
    parallel_iterations: bool = False  # 是否并行迭代

@dataclass
class ParallelFanOutNode(WorkflowNode):
    """并行扇出节点"""
    type: str = "parallel"
    fan_out: str                    # 扇出表达式
    body: WorkflowDefinition        # 每个扇出的执行体
    max_concurrency: int = 10       # 最大并发数

@dataclass
class SubWorkflowNode(WorkflowNode):
    """子流程节点"""
    type: str = "subworkflow"
    workflow_ref: str               # 子 Workflow 引用
    input_mapping: dict             # 输入映射

@dataclass
class DynamicNode(WorkflowNode):
    """动态节点（运行时确定子节点）"""
    type: str = "dynamic"
    resolver: str                   # LLM prompt 模板
    context: dict                   # 解析上下文
```

### 2.4 条件分支执行

```python
class ConditionExecutor:
    async def execute(
        self, node: ConditionNode, context: dict
    ) -> str:
        """Evaluate condition and return target node ID."""
        env = self._build_jinja_env(context)
        for branch in node.branches:
            if branch.expression == "default":
                return branch.target_node
            result = env.evaluate(branch.expression)
            if result:
                return branch.target_node
        raise NoMatchingBranchError(node.id)
```

### 2.5 循环执行

```python
class LoopExecutor:
    async def execute(
        self, node: LoopNode, context: dict
    ) -> list[WorkflowResult]:
        items = self._resolve_iterator(node.iterator, context)
        items = items[:node.max_iterations]

        if node.parallel_iterations:
            # 并行迭代
            tasks = [
                self._execute_iteration(node.body, item, context)
                for item in items
            ]
            return await asyncio.gather(*tasks)
        else:
            # 顺序迭代
            results = []
            for item in items:
                result = await self._execute_iteration(node.body, item, context)
                results.append(result)
            return results
```

### 2.6 动态节点解析

```python
class DynamicNodeResolver:
    async def resolve(
        self, node: DynamicNode, context: dict
    ) -> list[WorkflowNode]:
        """Use LLM to dynamically generate sub-nodes."""
        prompt = node.resolver.format(**context)
        llm = ChatOpenAI(model=settings.model, json_mode=True)
        response = await llm.ainvoke([SystemMessage(content=prompt)])
        plan = json.loads(response.content)
        return [WorkflowNode(**n) for n in plan.get("nodes", [])]
```

## 3. Phase 拆分

| Phase | 名称 | 目标 | 关键交付物 | 预估工作量 |
|-------|------|------|-----------|-----------|
| Phase 1 | Condition Node | 条件分支执行 | ConditionNode、Jinja2 表达式引擎 | 2-3d |
| Phase 2 | Loop Node | 循环遍历（顺序+并行） | LoopNode、迭代数据源、max_iterations | 3-4d |
| Phase 3 | Parallel Fan-out | 并行扇出 | ParallelFanOutNode、concurrency 控制 | 2-3d |
| Phase 4 | SubWorkflow | 子流程嵌套 | SubWorkflowNode、递归执行 | 2-3d |
| Phase 5 | Dynamic Node | 运行时节点生成 | DynamicNodeResolver、LLM 驱动模板 | 3-4d |
| Phase 6 | 集成测试 | 组合控制流测试 | 复杂 Workflow 场景测试 | 2-3d |

## 6. 验收标准

- [ ] AC1: 条件分支根据运行时数据正确选择执行路径
- [ ] AC2: 循环遍历数组数据，每次迭代独立执行
- [ ] AC3: 并行扇出 N 个实例并正确收集结果
- [ ] AC4: 子流程作为 DAG 节点透明嵌套执行
- [ ] AC5: 动态节点根据 LLM 输出生成正确的子节点列表
- [ ] AC6: 循环超过 max_iterations 自动终止

## 7. 风险与注意事项

- **无限循环**：依赖 max_iterations 硬限制，需合理默认值
- **动态节点不确定性**：LLM 生成的节点可能格式错误，需结构化验证
- **循环内错误**：单次迭代失败不应中止整个循环（可配置 fail_fast）
